# Reviewer Agent

Code review AMP agent with review tools, hooks, and custom agents.

Generated by swe_builder AMP for a TypeScript/Node copilot-sdk agent.

## Quickstart

```bash
npm install
npm run build
npm run dev -- "Hello from AMP"
```

You can also set `AMP_INITIAL_PROMPT` and run `npm start` after building. If no initial prompt is provided, the agent starts and keeps the session open for inbox or external events.

## Environment

Copy `.env.example` to `.env` and provide values before running. The generated code reads token variables directly from `process.env` when configured in the AMP manifest.

## Wired extensibility surfaces

| id | sdkSurface |
| --- | --- |
| tools | SessionConfig.tools (DefineTool / define_tool / DefineTool[T,U]) |
| customAgents | SessionConfig.customAgents |
| defaultAgent | SessionConfig.defaultAgent |
| hooks | SessionConfig.hooks (preToolUse / postToolUse / userPromptSubmitted / sessionStart / sessionEnd / errorOccurred) |
| permissions | SessionConfig.onPermissionRequest |
| systemMessage | SessionConfig.systemMessage (customize / append / replace) |
| streaming | SessionConfig.streaming |
| communication | AMP-ACS (Agent Communication Standards) - broadcast/inbox/handoff helpers generated alongside the SDK code. |

## Generated surfaces and notes

- Tools: `fetch_pr_diff`, `lint_check`, `post_review_comment` are registered in `SessionConfig.tools`.
  - `fetch_pr_diff` uses generated `static` stub logic.
  - `lint_check` uses generated `static` stub logic.
  - `post_review_comment` uses generated `echo` stub logic.
- Permissions: mode `allowList` is wired as `SessionConfig.onPermissionRequest`.
  - allowList rules auto-approve matching tool requests, then fall back to approveAll to avoid deadlock.
- Custom agents: 2 agent persona(s) are generated.
- Hooks: generated starters live under `src/hooks/` and are attached to `SessionConfig.hooks`.
- System message: AMP systemMessage configuration is marshalled at startup.
- Broadcast: session lifecycle events are emitted to stdout as JSONL envelopes.
- Initial prompt: pass it as the first CLI argument or set `AMP_INITIAL_PROMPT`.

User-provided handlers referenced by the AMP manifest are loaded relative to the source manifest directory. Implement those modules before using the corresponding generated stubs in production.
